Project Background

Bridging Local Code to Production Cloud

Understanding why modern cloud hosting replaces traditional on-premise development for reliable web deployment.

Local Laptop Hosting

Traditional / Local Environment

  • ❌ Zero High Availability: Website terminates immediately when the laptop goes to sleep or loses power.
  • ❌ No Public Access: Localhost endpoints (e.g. localhost:8000) are inaccessible to external visitors without router port forwarding.
  • ❌ No Health Monitoring: Hardware crashes and high memory usage go unnoticed without telemetry.
  • ❌ High Vulnerability: Exposing personal home networks introduces severe security risks.
AWS Cloud Architecture

Cloud-Based Hosting System

  • ✅ 24/7 Global Uptime: AWS EC2 virtual machines guarantee continuous availability backed by Amazon infrastructure.
  • ✅ Global Public IPv4: Reachable anywhere across the internet via standard web ports (Port 80 HTTP).
  • ✅ Automated Observability: Amazon CloudWatch actively tracks CPU usage and triggers threshold alerts.
  • ✅ Virtual Firewalls: AWS Security Groups enforce granular ingress/egress filtering rules.

Engineering Lifecycle

How It Works

A structured 5-step operational pipeline from local development to cloud production monitoring.

1
Phase 1 Source Code & Version Control

Local Development & Git Repository

The website is developed using standard, lightweight HTML5, CSS3, and vanilla JavaScript without heavy external frameworks. Code revisions are version-controlled using Git and pushed to GitHub for collaborative backup.

git add . && git commit -m "feat: design modern cloud website" && git push
2
Phase 2 Cloud Compute & Networking

EC2 Provisioning & Security Group Hardening

An Amazon EC2 t3.micro virtual instance running Ubuntu 22.04 LTS is launched in the Mumbai region. A custom Security Group (fcc-web-sg) is attached, permitting incoming web requests on Port 80 and restricting SSH Port 22 to administrator IP.

aws ec2 run-instances --image-id ami-0fa52f1a01deb1658 --instance-type t3.micro --security-group-ids sg-0464...
3
Phase 3 Web Server Automation

Apache Installation & File Deployment

The automated deployment script (deploy.sh) executes on the instance via SSH. It installs the Apache HTTP server, transfers website assets into /var/www/html/, assigns www-data permissions, and verifies service uptime.

chmod +x deploy.sh && ./deploy.sh # Automatically configures Apache & deploys web root
4
Phase 4 Client Delivery

Public HTTP Web Delivery

Users open the EC2 public IPv4 address (http://13.204.82.29/) in any browser. Apache processes the HTTP request, retrieves files from the disk, and returns a 200 OK response with complete styled web content.

curl -I http://13.204.82.29/ # Returns HTTP/1.1 200 OK with Apache/2.4 (Ubuntu) headers
5
Phase 5 Observability

CloudWatch Real-Time Telemetry & Alarms

Amazon CloudWatch polls hypervisor-level CPU utilization and status checks every 5 minutes. The HighCPUUtilization-fcc-web-server alarm actively monitors for traffic spikes to ensure high availability.

aws cloudwatch put-metric-alarm --alarm-name HighCPUUtilization-fcc-web-server --threshold 80
